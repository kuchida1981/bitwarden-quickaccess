# vault-backend-service

## Purpose

`bw serve` を子プロセスとして起動・監視し、HTTP経由でのvault操作(状態取得・アンロック・ロック・アイテム検索・アイテム取得・TOTP取得)を提供する内部バックエンドサービス。認証・vault復号・TOTP計算といったセキュリティ上リスクの高い処理をBitwarden公式実装の `bw serve` に委譲し、常駐GUIアプリ(Tauri製)のUI層(後続change)から参照される内部状態(ロック済み/アンロック済み)を保持する。

## Requirements

### Requirement: bw serve プロセスのライフサイクル管理
本サービスは、アプリ起動時に `bw serve` を子プロセスとして起動し、アプリ終了時に確実に終了させ、子プロセスが予期せず終了した場合はそれをアプリ内部状態に反映しなければならない(SHALL)。

#### Scenario: アプリ起動時にbw serveが起動する
- **WHEN** バックエンドサービスが初期化される
- **THEN** `bw serve` 子プロセスが起動し、起動成功がアプリ内部状態に記録される

#### Scenario: アプリ終了時にbw serveが終了する
- **WHEN** アプリケーションが終了処理に入る
- **THEN** 起動中の `bw serve` 子プロセスが終了される

#### Scenario: bw serveが予期せず終了する
- **WHEN** 起動済みの `bw serve` 子プロセスがクラッシュ等で終了する
- **THEN** アプリ内部状態が「バックエンド未接続」に更新される

### Requirement: 動的ポート割り当てとlocalhost限定バインド
本サービスは、`bw serve` の待受ポートを起動のたびに動的に選択し、`--hostname localhost` を指定して外部ネットワークに一切晒してはならない(SHALL NOT)。

#### Scenario: 空きポートが選択される
- **WHEN** `bw serve` を起動する
- **THEN** 使用中でない空きポート番号が選ばれ、`bw serve --hostname localhost --port <選ばれたポート>` として起動される

### Requirement: bw serve CLI 前提チェック
本サービスは、`bw serve` 起動前に `bw` CLI が存在し、`serve` サブコマンドをサポートするバージョンであることを確認し、満たさない場合は起動を中止してエラー状態を返さなければならない(SHALL)。

#### Scenario: bw CLIが見つからない
- **WHEN** バックエンドサービスの初期化時に `bw` コマンドが見つからない
- **THEN** `bw serve` を起動せず、CLI未検出のエラー状態を返す

### Requirement: bw serve HTTP API クライアントラッパー
本サービスは、起動中の `bw serve` に対して、状態取得・アンロック・ロック・アイテム検索・アイテム取得・TOTP取得の各操作をHTTP経由で実行する内部インターフェースを提供しなければならない(SHALL)。

#### Scenario: ロック状態を取得できる
- **WHEN** 状態取得インターフェースが呼び出される
- **THEN** `bw serve` の `/status` エンドポイントへのHTTPリクエスト結果に基づき、ロック済みかアンロック済みかが返る

#### Scenario: ロック中はアイテム検索が失敗を返す
- **WHEN** vaultがロックされた状態でアイテム検索インターフェースが呼び出される
- **THEN** `bw serve` からの `Vault is locked.` 相当のエラーがそのまま呼び出し元に伝播する

#### Scenario: アンロック後はアイテム検索が成功する
- **WHEN** vaultがアンロックされた状態でアイテム検索インターフェースが検索語付きで呼び出される
- **THEN** 検索語に一致するアイテム一覧が返る

#### Scenario: TOTPコードを取得できる
- **WHEN** アンロック済みの状態で、TOTPを持つアイテムのIDを指定してTOTP取得インターフェースが呼び出される
- **THEN** 現在時刻に対応するTOTPコードが返る

### Requirement: ロック状態の内部保持
本サービスは、直近のアンロック/ロック操作の結果をアプリ内部状態として保持し、UI層(後続change)から参照可能にしなければならない(SHALL)。

#### Scenario: アンロック成功後に内部状態が更新される
- **WHEN** アンロックインターフェースの呼び出しが成功する
- **THEN** アプリ内部状態が「アンロック済み」に更新される

#### Scenario: ロック実行後に内部状態が更新される
- **WHEN** ロックインターフェースが呼び出される
- **THEN** アプリ内部状態が「ロック済み」に更新される
