# vault-backend-service

## Purpose

`bw serve` を子プロセスとして起動・監視し、HTTP経由でのvault操作(状態取得・アンロック・ロック・アイテム検索・アイテム取得・TOTP取得)を提供する内部バックエンドサービス。認証・vault復号・TOTP計算といったセキュリティ上リスクの高い処理をBitwarden公式実装の `bw serve` に委譲し、常駐GUIアプリ(Tauri製)のUI層(後続change)から参照される内部状態(ロック済み/アンロック済み)を保持する。

## Requirements

### Requirement: bw serve プロセスのライフサイクル管理
本サービスは、アプリ起動時に `bw serve` を子プロセスとして起動し、アプリ終了時に確実に終了させ、子プロセスが予期せず終了した場合はそれをアプリ内部状態に反映しなければならない(SHALL)。起動確認(readinessポーリング)が完了する前に子プロセスが終了した場合は、それがアプリ終了処理による明示的な終了要求でない限り、原因を問わず起動失敗とみなし、ポートを再取得したうえで最大3回まで自動的に再試行しなければならない(SHALL)。再試行の上限に達した場合は、従来通りアプリ内部状態を「バックエンド未接続」に更新し、エラーメッセージを記録しなければならない(SHALL)。起動確認の完了を待っている間にアプリ終了処理による明示的な終了要求を受けた場合は、再試行を行わずそのまま処理を終了しなければならない(SHALL NOT retry)。

#### Scenario: アプリ起動時にbw serveが起動する
- **WHEN** バックエンドサービスが初期化される
- **THEN** `bw serve` 子プロセスが起動し、起動成功がアプリ内部状態に記録される

#### Scenario: アプリ終了時にbw serveが終了する
- **WHEN** アプリケーションが終了処理に入る
- **THEN** 起動中の `bw serve` 子プロセスが終了される

#### Scenario: bw serveが予期せず終了する
- **WHEN** 起動確認完了後の `bw serve` 子プロセスがクラッシュ等で終了する
- **THEN** アプリ内部状態が「バックエンド未接続」に更新される

#### Scenario: 起動確認前にbw serveが終了し、再試行で成功する
- **WHEN** `bw serve` 起動確認(readinessポーリング)が完了する前に子プロセスが終了する
- **THEN** アプリ内部状態は変更されないまま、新しいポートで `bw serve` の起動が再試行される
- **THEN** 再試行が起動確認に成功した場合、アプリ内部状態は通常通り更新される

#### Scenario: 起動確認前の終了が上限回数まで続く
- **WHEN** `bw serve` 起動確認が完了する前の終了が3回連続で発生する
- **THEN** アプリ内部状態が「バックエンド未接続」に更新され、起動に失敗した旨のエラーメッセージが記録される

#### Scenario: 再試行の起動確認待機中にアプリが終了する
- **WHEN** 起動確認(readinessポーリング)を待っている間にアプリケーションが終了処理に入る
- **THEN** 起動中の `bw serve` 子プロセスが終了され、新たな再試行は行われない

### Requirement: 動的ポート割り当てとlocalhost限定バインド
本サービスは、`bw serve` の待受ポートを起動のたびに動的に選択し、`--hostname 127.0.0.1` を指定して外部ネットワークに一切晒してはならない(SHALL NOT)。

#### Scenario: 空きポートが選択される
- **WHEN** `bw serve` を起動する
- **THEN** 使用中でない空きポート番号が選ばれ、`bw serve --hostname 127.0.0.1 --port <選ばれたポート>` として起動される

### Requirement: bw serve CLI 前提チェック
本サービスは、`bw serve` 起動前に `bw` CLI が存在し、`serve` サブコマンドをサポートするバージョンであることを確認し、満たさない場合は起動を中止してエラー状態を返さなければならない(SHALL)。

`bw` 実行ファイルの所在は、以下の順序で最初に見つかったものを採用しなければならない(SHALL)。

1. 設定ファイル(`$XDG_CONFIG_HOME/bw-quickaccess/bw_path.txt`。`XDG_CONFIG_HOME` が未設定の場合は `~/.config/bw-quickaccess/bw_path.txt`)に書かれた絶対パス。ファイルが存在し、かつ記載されたパスが実在する実行可能ファイルを指す場合に限り採用する。
2. 既知のインストール先を先頭から順に確認する: `/opt/homebrew/bin/bw` → `/usr/local/bin/bw`。
3. 上記いずれでも見つからない場合、`"bw"` をそのまま実行コマンドとして用いる(現在のプロセスが継承しているPATH上での解決に委ねる、最終フォールバック)。

いずれの方法でも実行可能な `bw` に到達できなかった場合(3のフォールバックも失敗した場合)は、`bw serve` を起動せず、CLI未検出のエラー状態を返さなければならない(SHALL)。このエラー状態には、設定ファイルにパスを明示指定する方法の案内を含めなければならない(SHALL)。

#### Scenario: 設定ファイルで指定したパスのbwが使われる
- **WHEN** 設定ファイルに実在する実行可能な `bw` の絶対パスが書かれている
- **THEN** 既知のインストール先やPATHに関わらず、設定ファイルに書かれたパスの `bw` が使用される

#### Scenario: 設定ファイルが無い場合は既知のインストール先が使われる
- **WHEN** 設定ファイルが存在しない、または記載されたパスが実行可能ファイルとして存在しない
- **AND** 既知のインストール先(`/opt/homebrew/bin/bw` または `/usr/local/bin/bw`)に実行可能な `bw` が存在する
- **THEN** 既知のインストール先のうち先に見つかったものの `bw` が使用される

#### Scenario: 設定ファイルにも既知のインストール先にも無い場合はPATHにフォールバックする
- **WHEN** 設定ファイルが存在せず、既知のインストール先にも実行可能な `bw` が存在しない
- **THEN** 現在のプロセスが継承しているPATHの解決に委ねて `"bw"` を実行しようとする

#### Scenario: bw CLIが見つからない
- **WHEN** 設定ファイル・既知のインストール先・PATHのいずれによっても実行可能な `bw` に到達できない
- **THEN** `bw serve` を起動せず、CLI未検出のエラー状態を返す
- **THEN** エラー状態には、設定ファイルにパスを明示指定する方法の案内が含まれる

### Requirement: bw serve HTTP API クライアントラッパー
本サービスは、起動中の `bw serve` に対して、状態取得・アンロック・ロック・アイテム検索・アイテム取得・TOTP取得の各操作をHTTP経由で実行する内部インターフェースを提供しなければならない(SHALL)。

#### Scenario: ロック状態を取得できる
- **WHEN** 状態取得インターフェースが呼び出される
- **THEN** `bw serve` の `/status` エンドポイントへのHTTPリクエスト結果に基づき、ロック済みかアンロック済みかが返る

#### Scenario: ロック中はアイテム検索が失敗を返す
- **WHEN** vaultがロックされた状態でアイテム検索インターフェースが呼び出される
- **THEN** `bw serve` からの `Vault is locked.` 相当のエラーがそのまま呼び出し元に伝播する

#### Scenario: アンロック後はアイテム検索が成功する
- **WHEN** vaultがアンロックされた状態でアイテム検索インターフェースが検索語付きで呼び出される
- **THEN** 検索語に一致するアイテム一覧が返る

#### Scenario: TOTPコードを取得できる
- **WHEN** アンロック済みの状態で、TOTPを持つアイテムのIDを指定してTOTP取得インターフェースが呼び出される
- **THEN** 現在時刻に対応するTOTPコードが返る

### Requirement: ロック状態の内部保持
本サービスは、直近のアンロック/ロック操作の結果をアプリ内部状態として保持し、UI層(後続change)から参照可能にしなければならない(SHALL)。

#### Scenario: アンロック成功後に内部状態が更新される
- **WHEN** アンロックインターフェースの呼び出しが成功する
- **THEN** アプリ内部状態が「アンロック済み」に更新される

#### Scenario: ロック実行後に内部状態が更新される
- **WHEN** ロックインターフェースが呼び出される
- **THEN** アプリ内部状態が「ロック済み」に更新される

### Requirement: ログイン中アカウントのメールアドレス取得
本サービスは、状態取得インターフェースの戻り値に、ログイン中アカウントのメールアドレスを含めなければならない(SHALL)。`bw serve` のレスポンスに含まれない場合は、含めなくてよい(MAY)。

#### Scenario: アンロック済み状態でメールアドレスが取得できる
- **WHEN** アンロック済みの状態で状態取得インターフェースが呼び出される
- **THEN** 戻り値にログイン中アカウントのメールアドレスが含まれる

#### Scenario: ロック中でもメールアドレスが取得できる
- **WHEN** ロックされた状態で状態取得インターフェースが呼び出される
- **THEN** 戻り値にログイン中アカウントのメールアドレスが含まれる

### Requirement: アイテムのアイコン情報取得
本サービスは、アイテム検索・アイテム取得インターフェースの戻り値に、アイテムごとのアイコン取得に用いるドメイン情報(`login.uris[0].uri` から抽出したホスト名)を含めなければならない(SHALL)。情報が得られない(URIを持たない等)アイテムについては、アイコン関連情報を含めなくてよい(MAY)。

#### Scenario: URIを持つアイテムにアイコン関連情報が含まれる
- **WHEN** `login.uris` にURIを持つアイテムを検索・取得する
- **THEN** 戻り値にそのアイテムのアイコン取得に用いるドメイン情報が含まれる

#### Scenario: URIを持たないアイテムにはアイコン関連情報が含まれない
- **WHEN** `login` を持たない、または `login.uris` が空のアイテムを検索・取得する
- **THEN** 戻り値にそのアイテムのアイコン関連情報は含まれない
