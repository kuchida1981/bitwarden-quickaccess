## Context

`quickaccess-search-ui` により検索・一覧・ヒント表示までは実装済みだが、実際のコピー/ブラウザ起動アクションと自動ロックがまだない。現行TUI(`bin/bw-quickaccess`)のコピー機能は過去に2度、キーバインドの衝突・環境依存で作り直されている(`fix-copy-keybind-conflict`: fzfデフォルトキーとの衝突、`fix-copy-keybind-meta-dependency`: ターミナルのOption=Metaキー設定への依存)。ただしこれらは**ターミナル/fzf特有の問題**(Altキーがエスケープシーケンスとして送られる、fzfの組み込みキーバインドと衝突する)であり、ネイティブGUIアプリではOSから実際の修飾キー(⌘/⇧/⌥)がそのままイベントとして届くため、同種の問題は原理的に発生しない。ただし別の環境依存(後述)には注意が必要。

## Goals / Non-Goals

**Goals:**
- フォーカス行に対する `⌘C`(ユーザー名)/`⌘⇧C`(パスワード)/`⌥⌘C`(TOTP)コピーを実装する。
- `Enter` によるブラウザ起動を実装する。
- コピー結果フィードバック表示を実装する。
- アイドルタイマーによる自動ロック(既定15分)を実装する。

**Non-Goals:**
- システムスリープ/画面ロックと連動した即時ロック(将来の改善候補)。
- 自動ロックのタイムアウト値をユーザーが設定変更するUI(既定値固定)。

## Decisions

### 1. コピー/TOTP取得アクションはRustコア内で完結させ、平文の秘匿値をWebView側JSに渡さない

`invoke('copy_field', { itemId, field })` の形でTauri commandを呼び、Rust側で `bw-serve-backend` からユーザー名/パスワード/TOTPを取得し、そのままクリップボードへ書き込む。WebView側のJSは「どのフィールドをコピーしたか」というメタ情報のみを扱い、パスワードやTOTPコードの実値を受け取らない。これは既存 `lib/clipboard.sh` の「値は必ず標準入力経由で渡し、コマンドライン引数には載せないこと」という設計思想(秘匿値の露出面を最小化する)を踏襲したものである。

### 2. ショートカットキーは「ウィンドウ内フォーカス時のみ有効な通常のキーイベント」として実装し、OSグローバルホットキー登録はしない

`⇧⌘Space`(`menubar-hotkey-shell` で実装済み)とは異なり、`⌘C`/`⌘⇧C`/`⌥⌘C`/`Enter` はポップアップウィンドウが表示されフォーカスを持っている間のみ有効であればよい。OSレベルのグローバルホットキーとして登録するのではなく、WebView内のkeydownイベントリスナーで処理する。ただし `⌘C` はOS標準の「テキストをコピー」ショートカットと衝突しうるため、**検索ボックスにフォーカスがある間は通常のテキストコピーを妨げず、一覧の行にフォーカスがある間のみ本アクションとして扱う**(フォーカス対象で挙動を分岐させる)。

### 3. コピー/ブラウザ起動後はポップアップウィンドウを閉じる

1Password Quick Accessと同様、アクション実行後は即座にウィンドウを非表示にする。フィードバック表示(成功/失敗)はウィンドウを閉じる前の短い時間、または次回ウィンドウを開いた際に直前の結果として一瞬表示する形とする(具体的な表示タイミングは実装時に体感で調整)。

### 4. アイドルタイマーはRustコア側で一元管理する

タイマーの起点・リセットをフロントエンド(WebView)側の各画面に分散させると実装漏れが起きやすいため、`bw-serve-backend` が提供するコマンド呼び出し(unlock/search/get item/get totp)のたびにRustコア内のアイドルタイマーをリセットする一元的な仕組みとする。タイムアウト(既定15分)に達したら `bw-serve-backend` の `/lock` を呼び出し、内部状態を「ロック済み」に更新する。

## Risks / Trade-offs

- [`⌘C` の挙動分岐(検索ボックス vs 一覧行)の実装を誤ると、意図しないタイミングで通常のテキストコピーを妨げる、または逆にコピー機能が発火しない] → 実装時にフォーカス状態の判定ロジックを丁寧にテストする。
- [アイドルタイマーによる自動ロックが、ユーザーが一覧を眺めているだけの時間(操作なし)をアイドルとみなしてロックしてしまう] → 現行TTL方式で既に受容されている挙動であり、本changeでも踏襲する。
- [コピー実行後に即座にウィンドウを閉じる挙動が、フィードバックメッセージを確認する間もなく画面が消えてしまう体感になる可能性] → 実装時に体感で表示時間を調整する。

## Migration Plan

- `quickaccess-search-ui` のUIにアクション実行ロジックを追加する形で、既存コードへの破壊的変更はない。
- 本changeの完了をもって、GUIアプリが現行TUIの主要機能を一通り代替できるようになる(TUI自体の削除は `gui-distribution-and-tui-removal` で行う)。
- ロールバックはコミットのrevertで対応可能。

## Open Questions

- コピー成功/失敗フィードバックの具体的な表示方法(ウィンドウを閉じる前に一瞬表示する / トレイアイコンの一時変化 等)は実装時に決定する。
- アイドルタイマーの正確なリセット条件(ウィンドウ表示イベントも含めるか等)は実装時に詰める。
