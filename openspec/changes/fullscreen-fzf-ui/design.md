## Context

現状のアーキテクチャ:
- `lib/search.sh` / `lib/fields.sh` は fzf を `--height=80%` で起動しており、ウィンドウ内表示(スクロールバックは隠れない)。
- コピー結果のフィードバックは `BWQA_COPY_STATUS_FILE` に1行書き込み、fzf の `transform-border-label` バインドで読み出して画面に反映する仕組みが既にある(`openspec/specs/copy-feedback/spec.md`)。ただしこれは `execute-silent` が**同期的にブロックして完了した後**にしか発火せず、処理中の表示はできない。
- `lib/fields.sh:128-131` のコメントに「execute-silent 経由の子プロセスは標準出力を一切見せないため、ローディング表示にはヘッダー書き換え等の別の仕組みが必要で、別 change で検討する」と明記されている。本 change がその「別 change」に当たる。
- fzf の man page 調査により、`every(N)`(タイマーイベント、v0.73.0〜)と `bg-transform-*`(非同期版 transform、v0.63.0〜)を組み合わせることで、fzf のイベントループをブロックせずに定期的な画面更新(スピナー)が実現できることを確認済み。
- issue #16 の探索(#32 に切り出し済み)で、起動直後の `bw unlock` フェーズおよび実行中のセッション切れ対応は本 change のスコープ外と決定済み。

## Goals / Non-Goals

**Goals:**
- 検索画面・フィールド選択画面を fzf ネイティブのフルスクリーン(alternate screen buffer)表示に変更する。
- フィールドコピー処理中、結果が確定するまでの間、スピナー等の進行状況をボーダーラベルに表示する。
- fzf バージョンによる機能の出し分け(if 分岐)を増やさない。必要な機能を持つバージョンを最低要件として要求する。

**Non-Goals:**
- 起動直後の `bw unlock` フェーズのフルスクリーン化・モーダル化(issue #32)。
- ツール実行中のセッション切れ検知・マスターパスワード再入力(issue #32)。
- vault 一覧取得・アイテム詳細取得(いずれも fzf 起動前の処理)のスピナー化。これらは現行の `bwqa_log` による1行メッセージ表示のまま変更しない(pre-fzf の処理であり、`loading-feedback` spec の既存シナリオはそのまま維持する)。

## Decisions

### 1. フルスクリーン化は `--height` オプションを外すだけで実現する

fzf の man page に「`--height` は fullscreen の代わりに使うオプション」と明記されている通り、`--height` を渡さないことが fzf 本来のフルスクリーンモードであり、alternate screen buffer への切り替え・復元は fzf 自身が担う。`tput smcup`/`rmcup` を自前で呼ぶ必要はない。

代替案として検討したが採用しなかったもの:
- 自前で `tput smcup`/`rmcup` を呼ぶ: fzf が既にこれを内部でやっているため冗長で、後始末(trap 設計)の責任も増える。

### 2. コピー中スピナーは `execute-silent` のバックグラウンド化 + `every(N)` + `bg-transform-border-label` で実現する

`__copy-field` サブコマンドの起動を `execute-silent(... &)` としてバックグラウンドジョブ化し、fzf 自体のイベントループをブロックしないようにする。処理の進行状況は次の2つの状態を持つ小さな状態ファイル(ロックファイル)で表現する:

- コピー処理開始時: ロックファイル(例: `$BWQA_CACHE_DIR/copy-lock`)を作成
- コピー処理終了時(成功/失敗いずれも): ロックファイルを削除し、`BWQA_COPY_STATUS_FILE` に最終メッセージを書き込む

ボーダーラベルの描画は新設する `__copy-status` サブコマンド(`bin/bw-quickaccess __copy-status`)に一本化する。このサブコマンドは:
- ロックファイルが存在する → 経過時間からスピナーのフレームを算出し、「コピー中...」等のメッセージと合わせて出力
- ロックファイルが存在しない → `BWQA_COPY_STATUS_FILE` の内容(既存の最終結果メッセージ)をそのまま出力

fzf 側のバインドは以下の形になる(概念図。実際のクォート等は実装時に詰める):
```
--bind "ctrl-r:execute-silent(...__copy-field password &)+transform-border-label(...__copy-status)"
--bind "every(0.15):bg-transform-border-label(...__copy-status)"
```
`execute-silent` 直後の同期 `transform-border-label` は、`every(N)` の最初のティックを待たずに即座に「コピー中...」を出すための保険(体感の初動レスポンスを上げる)。

代替案として検討したが採用しなかったもの:
- **`bw list items` 等と同様にヘッダー(`--header`)を書き換える**: ヘッダーは fzf 全体で1つの静的領域だが、検索クエリのヒント表示など他の用途と競合しやすいため、既存パターンを踏襲してボーダーラベルに統一した。
- **`transform` の同期版のみで擬似的にポーリングする**: man page に明記の通り同期 `transform-*` は実行中 fzf 全体をブロックするため、キー入力(Esc でのキャンセル等)を受け付けられなくなり不採用。

### 3. fzf 最低要件を 0.73.0 に引き上げ、バージョン分岐は行わない

`every(N)` は v0.73.0 で導入されたため、これを使う以上この version が必須になる。`bwqa_check_fzf_version` の `required` を書き換えるだけで済み、実装・テストの分岐が増えない。ユーザーとの合意により、フォールバック実装(旧バージョン向けの事後表示のみのパス)は作らない。

### 4. ロックファイルはグローバルに1つ

同時に複数のコピー操作が走ることは通常のユーザー操作では起きない(1つのキー入力に対して1つのバックグラウンドジョブ)。ロックファイルを操作ごとに一意にする複雑さは避け、`bwqa_copy_field_internal` の冒頭で作成し `trap ... EXIT` で確実に削除する、単純な単一ファイル方式とする。

## Risks / Trade-offs

- [フルスクリーン化により、ターミナルのスクロールバックが一時的に隠れる体験になる] → 既にユーザーと合意の上で常時適用と決定。README に明記する。
- [`every(N)` の間隔が短すぎるとサブプロセス起動オーバーヘッドが増え、長すぎるとスピナーがカクつく] → 実装時に体感で調整する(0.1〜0.2秒程度を想定)。既存の `bwqa_version_ge` 等のテストパターンとは独立した見た目の調整なので、自動テストでは間隔値そのものより「ロックファイル有無で出力が切り替わること」を検証する。
- [fzf 0.73.0 未満のユーザーはツールが起動できなくなる(**BREAKING**)] → `bwqa_check_fzf_version` が起動時に明示的なエラーメッセージとアップグレード案内(`brew upgrade fzf` 等)を表示するため、無言の失敗にはならない。
- [連続キー入力でロックファイルの作成・削除が競合する] → 最悪でも「スピナー表示が少し長引く」程度の見た目上の影響に留まり、実際のコピー処理(クリップボードへの書き込み)自体の正しさには影響しない。

## Migration Plan

- `lib/preflight.sh` のバージョン定数変更、`lib/search.sh` / `lib/fields.sh` の fzf 起動オプション変更、`bin/bw-quickaccess` への `__copy-status` サブコマンド追加を1つの change としてまとめて実装する(機能的に分割しても中間状態に意味がないため)。
- README(日本語版・英語版)の必要要件セクションを更新する。
- ロールバックが必要な場合は git revert で対応可能(データマイグレーションは発生しない)。

## Open Questions

- `every(N)` の具体的な秒数、スピナーのフレーム/文字セットは実装時に体感で決定する(design 上はロックファイルベースの状態遷移のみを規定する)。
