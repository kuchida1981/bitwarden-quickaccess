## Context

コピー結果フィードバックは `app/dist/app.js` の `showFeedback()` が表示し、`FEEDBACK_DISPLAY_MS`(700ms)後に `hide_popup` コマンドを呼んでウィンドウを隠す(`runAction`)。フィードバックのクリアは `handleShown()` 内の `showScreen()` 呼び出し時にのみ行われ、`showScreen` はフロントエンドが `POPUP_SHOWN_EVENT`(`app/src-tauri/src/popup.rs` の `toggle_popup` 表示分岐でのみ emit)を受けたときにしか呼ばれない。

`toggle_popup` は「表示中なら隠すだけ・非表示なら表示して emit」という単純トグルであるため、700ms のフィードバック表示中に素早く再トグルすると、非表示→表示の遷移が想定どおりに起きず、古いフィードバックが再表示画面に残ることがある。加えて `hidePopupTimer` はJS側のみで管理され、Rust側のウィンドウ表示状態と同期していない。

## Goals / Non-Goals

**Goals:**
- フィードバックが画面遷移イベント(`POPUP_SHOWN_EVENT`)の有無に関わらず、一定時間で必ず消える。
- ポップアップが非表示になる経路(`hide_popup` 呼び出し、`Focused(false)` によるブラー時の自動hide)で、次回表示時に必ずクリーンな状態から始まる。

**Non-Goals:**
- フィードバックの表示内容(文言・成功/失敗の判定ロジック)自体の変更。
- `toggle_popup` のトグル方式自体の再設計(単純トグルは維持する)。
- Rust側とJS側の状態を完全に一元管理する大掛かりな同期機構の導入。

## Decisions

- **フィードバックの消去は「独立タイムアウト」と「非表示イベントでのリセット」の二重化で保証する**。表示遷移(`POPUP_SHOWN_EVENT`)への依存を無くし、フィードバック自身が寿命を持つようにする。
  - 独立タイムアウト: `showFeedback()` 呼び出し時に専用のタイマー(2〜3秒)をセットし、経過後に自身でメッセージ要素をクリアする。既存の `hidePopupTimer`(700ms、ポップアップを隠すためのタイマー)とは別物として扱う。
  - 非表示イベントでのリセット: `hide_popup` コマンド(`commands.rs`)呼び出し時、および `popup.rs` の `Focused(false)` ブラー時の自動hide時に、Rust側から現在表示中のwebviewへ「フィードバックをクリアせよ」というイベントを emit する。あるいはフロントエンド側で `window.onFocusChanged`/`hide_popup` 呼び出し自体をフックしてクリアする(実装はagyに委譲する際に既存のイベント購読パターンに合わせて選択させる)。
- **`POPUP_SHOWN_EVENT` の処理自体は変更しない**。表示のたびに `handleShown()` → `showScreen()` が呼ばれる既存の流れは正しく機能しているため、そこに新しいクリア処理を追加するだけで十分(表示時にクリアされるパスは維持)。

## Risks / Trade-offs

- [独立タイムアウトの秒数が短すぎるとユーザーがメッセージを読み切れない/長すぎると次のフィードバックと誤認する] → 2〜3秒の範囲で実装し、動作確認時に体感で調整する。
- [Rust側からのクリアイベント追加により、表示中に無関係な再描画が走る可能性] → クリア処理はテキストのみのリセットとし、他のUI状態(検索結果・フォーカス位置)には影響させない。

## Migration Plan

既存動作への後方互換性は不要(バグ修正のみ)。ロールバックは通常のgit revertで対応可能。
