## Context

`lib/fields.sh` の `bwqa_run_field_screen()` は fzf の `execute-silent` バインド経由で `bwqa_copy_field_internal()`(`__copy-field` サブコマンドとして自プロセスを再帰起動)を呼び出す。fzf の仕様上 `execute-silent` は子プロセスの標準出力・標準エラー出力を一切ターミナルに表示しないため、`bwqa_log`(stderr 出力)によるフィードバックは機能しない。これは直前の change (`quick-ux-tweaks`) の実装中に tmux 上での検証で確認済みの制約であり、その design.md で「fzf のヘッダー/ラベル書き換えという別の仕組みが必要」として本 change に先送りされていた。

fzf の CHANGELOG を確認したところ、`change-border-label` / `transform-border-label` は fzf 0.37.0 で追加されている(`change-header` / `transform-header` は 0.40.0)。本リポジトリの現在の最低要件は `lib/preflight.sh` の `0.35.0` であるため、いずれの方式を採るにせよ引き上げが必要になる。`--header` は既存の操作説明(`Enter: 選択中の項目をコピー ctrl-p: ... 等`)をそのまま維持したいため、コピー結果は `--border-label` 側で表現し、バージョン引き上げ幅を最小(0.37.0)に抑える。

`bwqa_copy_field_internal()` は現在、コピーに失敗した場合(`bw` コマンド自体の失敗、または取得した値が空)を区別せず、`$BWQA_ERROR_LOG_FILE` に1行記録するのみで exit 1 する(fields.sh:94-117)。

既存 spec `credential-clipboard-copy` は「該当フィールドが存在しないアイテムを選んだ場合、フィールドが存在しない旨をユーザーに分かる形で示す」というシナリオを既に定義済みだが、リスト選択(存在しないフィールドの行はそもそも表示されない)を前提にした記述になっており、キーバインドショートカット(ctrl-u/p/t)経由での直接指定時にはこの要件は実装されていない。

## Goals / Non-Goals

**Goals:**
- フィールド選択画面でのコピー操作(Enter / ctrl-u / ctrl-p / ctrl-t)の成功・失敗を、fzf の `--border-label` を通じて画面上に表示する
- コピー対象フィールドが存在しない場合(値が空)と、`bw` コマンド自体が失敗した場合とを、メッセージ上で区別する
- フィードバック表示は自動で消さず、次のコピー操作や画面遷移まで表示し続ける(タイマーによる自動消去は実装しない)
- `bwqa_check_fzf_version()` の最低バージョンを `0.37.0` に引き上げ、README にも反映する

**Non-Goals:**
- 検索画面からの直接コピー(issue #3)は対象外。別 change で扱う。ただし `bwqa_copy_field_internal()` の呼び出し規約(item_id を引数からも受け取れるようにする等)を破壊しない形にはしておく
- `bw` コマンドのタイムアウト制御・リトライ・再認証ロジックの変更は対象外。既存の `bwqa_bw()` 等の再試行パターンへの変更は行わない
- ヘッダー(`--header`)自体を動的に書き換える方式(`change-header`/`transform-header`)は採用しない。将来的に必要になった場合は別途 fzf 0.40.0 への引き上げを検討する

## Decisions

- **表示先を `--border-label` にする**: `--header` は静的な操作説明を維持し続けたい一方、コピー結果は一時的な状態。両者を同じ領域に混在させると「今何が起きたか」と「常時の操作説明」が区別しにくくなる。`--border-label` を専用の状態表示領域として分離する。副次的効果として fzf 最低バージョンの引き上げ幅を 0.37.0 に抑えられる(`--header` 書き換えは 0.40.0 が必要)
- **`--border` の追加が必須**: `--border-label` は `--border` が有効な場合のみ描画される(fzf man page 参照)。現在の `bwqa_run_field_screen()` は `--border` を指定していないため、`--border=rounded`(デフォルトスタイル)を追加する。`--height=80% --reverse` レイアウトへの見た目の影響は実装時に目視確認する
- **結果の受け渡しは状態ファイル経由**: `execute-silent` の子プロセス(`__copy-field`)の標準出力は fzf からは見えないため、`bwqa_copy_field_internal()` が結果メッセージを1行、状態ファイル(例: `$BWQA_CACHE_DIR/copy-status`、`BWQA_ERROR_LOG_FILE` と同様の置き場所)に**上書き**で書き込み、`execute-silent(...)+transform-border-label(cat "$BWQA_COPY_STATUS_FILE")` のように `+` で連結したアクションで読み出す。fzf のアクションは同一キー入力に対して逐次(同期的)に実行されるため、書き込みと読み出しの間で競合は発生しない
- **失敗理由の区別**: `bw get <field> <item_id>` の終了コードを `|| true` で握りつぶさず変数に保持する。終了コード非ゼロなら「コピーに失敗しました」、終了コードゼロだが値が空なら「<フィールド名>は設定されていません」、成功なら「<フィールド名>をコピーしました」という3パターンのメッセージを出し分ける。フィールド名の日本語ラベルは `bwqa_build_field_rows()` で使っている表記(ユーザー名/パスワード/TOTP)に合わせる
- **メッセージに機密情報を含めない**: アイテム名・フィールドの値そのものは一切含めず、固定パターンの文言のみを使う(既存の「機密情報を標準出力に出力しない」要件の精神を踏襲)
- **状態ファイルは都度上書き**: 追記(append)にすると内容が肥大化し続けるため、`printf` で毎回上書きする。画面起動直後(まだ一度もコピーしていない状態)は `--border-label` の初期値(固定の空文字 or 案内文言)を使い、過去の実行で残った状態ファイルの中身は読みに行かない

## Risks / Trade-offs

- [`bw` コマンドがハングした場合、`execute-silent` がブロックし続け、画面が応答不能に見える] → 本 change のスコープ外(タイムアウト制御は別課題)。現状からの後退ではないため許容する
- [`--border-label` の表示幅が狭い環境では長いメッセージが切り詰められる可能性] → メッセージ文言を短く固定する(例: 15文字程度以内)ことで軽減する
- [fzf 最低バージョンの引き上げ(0.35.0 → 0.37.0)により、対象バージョン範囲のユーザーが preflight でエラーになる] → README とエラーメッセージで案内済みの範囲であり、破壊的だが軽微な変更として許容する
- [`--border` 追加によるレイアウト変化(行数減少等)] → 実装時に実機で目視確認し、`--height` の調整要否を判断する

## Open Questions

- 状態ファイルの正確なパス名・変数名(例: `BWQA_COPY_STATUS_FILE`)は実装時に確定する
- 「フィールド未設定」と「`bw` コマンド失敗」のメッセージの具体的な日本語文言は、実装時に確定する(design 上は3パターンの区別のみを決定事項とする)
