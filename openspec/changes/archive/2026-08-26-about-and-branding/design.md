## Context

現状のアイコンアセット(`app/src-tauri/icons/`)は以下の単色画像で、意匠が一切ない。

| ファイル | サイズ | 色 |
|---|---|---|
| `icon.png` / `128x128.png` / `128x128@2x.png` / `32x32.png` / `icon.icns` | 各種 | `#175DD3`(青。偶然にもBitwarden公式の青に酷似) |
| `tray-disconnected.png` | 32x32 | `#8C8C8C`(グレー) |
| `tray-locked.png` | 32x32 | `#D97706`(オレンジ) |
| `tray-unlocked.png` | 32x32 | `#16A34A`(グリーン) |

`app/src-tauri/src/tray.rs` の `icon_bytes_for()` がこれらを `include_bytes!` で埋め込み、トレイアイコンとして状態に応じて切り替えている(`tray-*.png` は macOSの「テンプレート画像」指定はされておらず、単純なフルカラー画像として表示される)。

トレイメニューには `VERSION_ITEM_ID` の非活性項目でバージョン番号のみ表示されており、アプリ名表示・外部リンクは存在しない。

事前にSVGで新アイコン案を作成し、`rsvg-convert` でレンダリングしたプレビューをユーザーに確認済み(承認済み)。デザインは以下の通り。

- アプリ本体アイコン: ラウンド角正方形(バイオレット `#6C4CE0`)+ 白いシールド + バイオレットの雷マークのカットアウト
- トレイアイコン: シールド形状のみ(雷マークは32x32では潰れるため省略)、色は既存の状態色(グレー/オレンジ/グリーン)をそのまま維持

## Goals / Non-Goals

**Goals:**
- 承認済みのアイコンデザイン(SVGソース)から、必要な全サイズのPNGとICNSを生成し、既存アセットを差し替える
- トレイメニューにアプリ名・バージョン表示とGitHubリポジトリへのクリック可能なリンクを追加する
- 将来のデザイン修正のため、SVGソースをリポジトリに残す

**Non-Goals:**
- Bitwarden公式ロゴの完全な模倣(意図的に配色・意匠を変えている。issue #50の商標上の懸念に対応)
- macOSの「テンプレート画像」方式(単色+透過、OSが自動で配色)への変更。既存の状態別カラーリングの方式を維持する
- アイコンの動的テーマ対応(ライト/ダークモードでの自動切り替え等)
- トレイメニューからのアプリ内アップデートチェック機能

## Decisions

### 1. アイコンはSVGソースから生成する(AI画像生成は不採用)

`rsvg-convert`(SVG→PNGレンダリング)、ImageMagick(補助)、`iconutil`(PNG→ICNSパッケージング)はいずれもmacOS標準または既にインストール済みのCLIツールであり、新規の実行時依存にはならない(ビルド時にのみ使用し、生成済みのPNG/ICNSファイルをリポジトリにコミットするため、CI/エンドユーザーのビルド環境に影響しない)。

**代替案: agyのAI画像生成(`antigravity_image`)を使う** — 却下。テキストからの画像生成では、macOSの複数解像度・透過PNG・ICNSパッケージングといった正確な要件を満たす出力を安定して得るのが難しく、シールドのような幾何学的な意匠は自分でベクターパスを書いた方が正確・再現可能。実際に事前にSVGでドラフトを作成し、ユーザーの承認を得た上でこのdesign.mdを書いている。

### 2. アプリ本体アイコンの配色をBitwarden公式の青から変更する

既存のプレースホルダー(`#175DD3`)がBitwarden公式の青(`#175DDC`前後)に酷似していたため、そのまま「青いシールド」にすると本家との混同・商標上の懸念が残る(issue #50参照)。配色をバイオレット(`#6C4CE0`)に変更し、シールド内部に雷マーク(「クイック」を象徴)を配置することで、意匠・配色の両面でBitwarden公式と区別する。

### 3. トレイアイコンは形状のみ変更し、状態別の色分けは維持する

トレイアイコンの色(グレー/オレンジ/グリーン)は状態表示として既に機能しており、ユーザーが見た目で状態を判別する手がかりになっている。今回は「単色の四角ではなく識別可能な形状にする」ことが目的(issue #50の「何のツールか分からない」という指摘への対応)であり、状態色の意味を変える必要はないため、色は変更せずシールド形状だけを追加する。

### 4. SVGソースをリポジトリに残す

`app/src-tauri/icons/source/app-icon.svg` と `app/src-tauri/icons/source/tray-shield.svg`(色違い3種を生成する元になる、`fill` を状態色に差し替えたテンプレート)をリポジトリに追加する。将来、配色や意匠を調整する際にラスター画像から逆算する必要がないようにする。

### 5. トレイメニューへのアプリ名・バージョン表示は非活性の1項目にまとめる

既存の `version_item`(非活性、`バージョン: {version}` 表示)を、`{アプリ名} v{version}`(例: `bw-quickaccess v0.1.0`)を表示する1項目に置き換える。アプリ名は `app.package_info().name`(Tauriが `tauri.conf.json` の `productName` から提供する、既存の `env!("CARGO_PKG_VERSION")` と同様の「ビルド設定を単一の情報源とする」方針)から取得し、ハードコードしない。アプリ名自体は言語によらない固有名詞のため、i18nの `Messages` 構造体を経由せず、`tray.rs` 内で直接 `format!("{name} v{version}")` として組み立てる(バージョン番号と同様、翻訳を要しない値のため)。

### 6. リポジトリリンクは新規のクリック可能なメニュー項目にする

新規メニュー項目(`REPO_LINK_ITEM_ID`)を追加し、クリック時に `tauri_plugin_opener`(`commands.rs` の `open_in_browser` と同じ仕組み)で `https://github.com/kuchida1981/bitwarden-quickaccess` を既定のブラウザで開く。ラベル文言(「GitHubリポジトリを開く」/ "View on GitHub")は `i18n::Messages` に新しいフィールド(`repo_link_label`)として追加し、既存の `autostart_label` 等と同じパターンで日英を切り替える。

メニュー構成は以下の順序にする(既存の `version_item` を置き換える形):

```
状態表示
ホットキー表示
---
自動起動トグル
---
アプリ名 + バージョン(非活性)
GitHubリポジトリを開く(クリック可能)
終了
```

## Risks / Trade-offs

- [Risk] アイコンの見た目の変更は主観的な判断を伴うため、実装後に「印象が違う」となる可能性がある → [Mitigation] 実装前にプレビュー画像をユーザーに送付し、承認を得てからこのdesign.mdを書いている
- [Trade-off] SVGソースをリポジトリに追加することで、`app/src-tauri/icons/` 配下のファイル数が増える。将来的にビルドスクリプトでSVGから自動生成する仕組みにする選択肢もあるが、生成頻度が低い(アイコンはほぼ変更されない)ため、今回は生成済みファイルをコミットする方式のままとする
