## Why

`menubar-hotkey-shell` によりポップアップウィンドウの表示/非表示という骨格はできたが、中身がプレースホルダのままで実用にならない。本changeでは、ポップアップウィンドウに実際の検索ボックス・インクリメンタル検索結果一覧・マスターパスワードのアンロックフォームを実装し、現行TUIの検索体験(`fzf` によるインクリメンタル検索)に相当する機能をGUIで再現する。

## What Changes

- ポップアップウィンドウ内に、ロック状態に応じて2つの画面を切り替える(WebView上のHTML/CSS/JS)。
  - **ロック中**: マスターパスワード入力フォームを表示し、送信で `bw-serve-backend` の `/unlock` を呼び出す。成功時は検索画面に切り替わる。失敗時はエラーメッセージを表示する。
  - **アンロック済み**: 検索ボックスとインクリメンタル検索結果一覧を表示する。
- 検索ボックスへの入力のたびに(デバウンス付きで)`bw-serve-backend` のアイテム検索インターフェースを呼び出し、一覧を更新する。
- 一覧の各行に、アイテム名・ユーザー名等の要約を表示する。
- 行を上下矢印キーまたはマウスホバーでフォーカスした際、利用可能なショートカットヒント(`⌘C` ユーザー名コピー / `⌘⇧C` パスワードコピー / `⌥⌘C` TOTPコピー / `Enter` ブラウザで開く)を表示する。**本changeではヒント表示のみを扱い、実際のコピー/ブラウザ起動アクションの実行は `credential-actions-autolock` のスコープとする。**
- ポップアップウィンドウが表示されたら検索ボックスに自動的にフォーカスする。

## Capabilities

### New Capabilities
- `vault-unlock-prompt`: ポップアップウィンドウ内でのマスターパスワード入力によるアンロックUIを提供する。
- `incremental-item-search`: 検索ボックスへの入力に応じたインクリメンタルなアイテム検索結果一覧と、行フォーカス時のショートカットヒント表示を提供する。

### Modified Capabilities
(なし)

## Impact

- `menubar-hotkey-shell` で用意したポップアップウィンドウのプレースホルダを本changeの内容で置き換える。
- `bw-serve-backend` の `/unlock` および検索インターフェースに依存する。
- 実際のコピー/ブラウザで開くアクション実行ロジックは持たない(ヒント表示のみ)。
- 既存の `bin/bw-quickaccess` / `lib/*.sh` には影響しない。
- ユーザー向け影響: 開発ビルドを起動すると、ホットキーでマスターパスワード入力 → 検索 → 結果一覧の閲覧まで行えるようになる(コピー等のアクションはまだ実行できない)。
