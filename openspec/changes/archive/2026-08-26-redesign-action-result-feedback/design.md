## Context

現状、コピー等のアクション実行後は `showFeedback()` でテキストメッセージを表示し、成功/失敗にかかわらず700ms後に `hide_popup` を呼んでクイックアクセスを閉じる(`runAction`, `app/dist/app.js:345-363`)。このテキスト状態のクリアは `POPUP_SHOWN_EVENT` 受信時の `handleShown()` にのみ依存しており、静的なコードトレースでは「表示のたびに必ずクリアされる」はずだが、実際にはメッセージが再表示後も表示され続けるという報告(issue #65)があった。

この調査の過程で、そもそも成功時に「メッセージ表示」と「ポップアップが閉じる」という2つの成功シグナルを重ねて出している設計自体が冗長であるという指摘があった。また、キーボードショートカット経由のアクション(`executeItemAction`, `app.js:286-306`)は対象フィールドの有無を事前チェックしないため、失敗時にテキスト以外で結果を伝える手段が無く、これがテキスト状態管理の複雑化・残留バグの温床になっていた。

## Goals / Non-Goals

**Goals:**
- テキストによる結果フィードバックを廃止し、「フォーカス行の点滅(入力受付の合図、成功/失敗によらず必ず発生)」+「クイックアクセスの開閉(成功/失敗の合図)」という2段階の視覚フィードバックに統一する。
- ショートカット直押し・アクションメニュー経由のどちらの起動方法でも同一の実装で成立させる(`executeItemAction`/`runAction` が共通の入口であることを活かす)。
- 「キー入力が受け付けられたかどうか分からない」という曖昧さを、点滅を成功/失敗どちらでも必ず発生させることで解消する。

**Non-Goals:**
- アンロック画面のエラーメッセージ(`unlockError`)や、検索結果0件時のメッセージなど、コピー/ブラウザ起動アクション以外のテキストフィードバックの変更。
- `toggle_popup` のトグル方式自体の再設計。
- アクセシビリティ対応(スクリーンリーダー等)の強化。本アプリの現状のスコープ外として扱う。

## Decisions

- **点滅は成功/失敗によらず必ず発生させる**。点滅そのものは「入力を受け付けた」ことのみを意味し、結果の成否とは独立させる。これにより、点滅の実装は分岐不要になり単純化される。
  - 実装イメージ: フォーカス中の `<li class="focused">` に一時的なCSSクラス(例: `flash`)を付与し、CSSアニメーション終了後に自動でクラスを外す(`animationend` イベント、または `setTimeout`)。
- **成功/失敗の合図はクイックアクセスの開閉に一本化する**。成功時は点滅後に `hide_popup` を呼ぶ(現行の700msタイマーを、点滅アニメーションの完了を待つ形に置き換える)。失敗時は何も呼ばず、検索画面にとどまる(フォーカス・検索結果はそのまま維持)。
  - これにより issue #65 が問題にしていた「非表示イベントに依存したテキストクリア」という構造自体が無くなる。テキスト状態を持たないため、そもそも「残留」という概念が発生しない。
- **`#feedback` 要素・関連CSS・i18n文字列は削除する**。将来的に別の用途で「メッセージ表示」が必要になった場合は、その時点で新規に設計する(YAGNI)。
- **点滅アニメーションの長さは、既存の `FEEDBACK_DISPLAY_MS`(700ms)を参考値としつつ、点滅回数(例: 2〜3回明滅)から逆算した秒数に置き換える**。具体的な秒数・回数は実装時に体感で調整してよい(design上の必須要件にはしない)。

## Risks / Trade-offs

- [失敗時に何のテキストも出ないため、「なぜ失敗したか」の具体的な理由(TOTP未設定なのか、バックエンドエラーなのか)がユーザーに伝わらない] → 現状もアクションメニュー(矢印キー)を開けば `has_totp` 等でフィールドの有無を事前に確認できるため、直接ショートカットを使うユーザーは自己責任で対象フィールドの有無を把握する前提とする。将来的に必要性が高まれば、行に軽微なアイコン表示等を別途検討する(本changeのスコープ外)。
- [点滅アニメーションの視認性が低いと、失敗時に「何も起きなかった」と誤解される] → CSSアニメーションの色・回数は実装後に実機で確認し、必要なら調整する(tasks.mdに動作確認タスクを含める)。
- [既存の自動テスト(あれば)がテキストフィードバックの存在を前提にしている場合、修正が必要] → 実装時に既存テストを確認し、点滅・開閉挙動を検証するテストに置き換える。

## Migration Plan

既存動作への後方互換性は不要(UI挙動の変更のみ、外部インターフェースへの影響なし)。ロールバックは通常のgit revertで対応可能。
