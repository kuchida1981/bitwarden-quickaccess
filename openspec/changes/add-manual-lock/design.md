## Context

`BwServeClient::lock()`(`app/src-tauri/src/backend/http_client.rs`)は実装済みで、`AppState::set_locked()` も既存(`idle-auto-lock` の自動ロックが `watch_idle_timeout`(`main.rs`)から同じ組み合わせで呼んでいる)。既存の `unlock` コマンド(`commands.rs`)が同じパターン(`client_for(&state)` → API呼び出し → 状態更新)を持っており、これをそのまま踏襲できる。

トレイメニュー(`tray.rs`)は既に `AppState` の状態変化を購読して `status_item`(テキスト)と`icon`を更新するループを持っており、ここに「今すぐロック」項目の有効/無効切り替えを相乗りできる。

## Goals / Non-Goals

**Goals:**
- 検索画面のショートカット `⌘L` と、トレイメニューの「今すぐロック」の両方から明示的ロックを実行できるようにする(issue本文が両方を候補として挙げており、実装コストが小さいため両方対応する)。
- ロック実行後、ポップアップ表示中であれば即座にアンロック画面に切り替える。
- ロックはアンロック済みのときのみ意味を持つため、トレイメニュー項目はアンロック済みのときのみ有効化する。

**Non-Goals:**
- ロック実行の確認ダイアログ(「本当にロックしますか?」等)の追加。既存の自動ロックも確認なしで即座にロックしており、一貫性を優先する。
- ロックのショートカットキーのカスタマイズ機能。

## Decisions

- **`lock` コマンドは既存の `unlock` コマンドと同じパターンで実装する**: `client_for(&state)?` → `client.lock().await` → `state.set_locked()`。アイドルタイマーのリセットは行わない(ロックはセッションを終了させる操作であり、アイドルタイマーの延長とは無関係)。
- **トレイメニューのクリックハンドラから、`commands::lock` を直接呼び出す**(IPC経由ではなく、同一プロセス内の関数呼び出しとして)。`BwServeClient` 生成ロジックを `tray.rs` に重複実装しないための選択。
- **`⌘L` の処理は `searchBox` のkeydownリスナー内の早い段階(ヘルプ・アクションメニューのトグル判定と同じ並び)に置く**。既存の `handleActionShortcut` は「フォーカス中のアイテムが無ければ何もしない」ガードを持つが、ロックはアイテムの選択状態に依存しないため、そのガードの外側で処理する。
- **トレイメニュー項目の有効/無効は、既存の状態購読ループ(`status_item`/アイコン更新箇所)に相乗りして切り替える**(アンロック済みのときのみ有効)。

## Risks / Trade-offs

- [トレイメニューのロック処理が非同期(`tauri::async_runtime::spawn`)のため、失敗時にユーザーへフィードバックする手段がない] → 既存の自動起動トグル失敗時も `eprintln!` のみで、同水準の扱いとする。ロック失敗(バックエンド未接続等)は次にポップアップを開いた際の状態表示で気づける。
- [`⌘L` が既存のOS標準ショートカット(ロック画面呼び出し等)と衝突する可能性] → 本アプリはTauriのWebViewポップアップ内でのキー処理であり、OSのシステムショートカットとは独立して動作する(既存の `⌘C` 等と同様)。
