## Context

`menubar-hotkey-shell` によりポップアップウィンドウの表示/非表示という骨格ができたが、中身はプレースホルダのままである。本changeでは、ポップアップの中身(アンロックフォーム・検索ボックス・結果一覧)を実装し、`bw-serve-backend` が提供するインターフェースと接続する。

現行TUI(`lib/search.sh`)は `fzf` によるファジー検索を使っていたが、`bw serve` の `/list/object/items?search=...` が同等のファジーマッチを提供するかは未検証であり、実装時に確認が必要(Open Questions参照)。

## Goals / Non-Goals

**Goals:**
- ロック状態に応じてアンロックフォーム/検索画面を切り替えるポップアップUIを実装する。
- 検索ボックスへの入力に応じたインクリメンタル検索結果一覧を実装する。
- 行フォーカス時のショートカットヒント表示を実装する。
- ウィンドウ表示時の検索ボックスへの自動フォーカスを実装する。

**Non-Goals:**
- コピー/ブラウザで開くアクションの実際の実行(`credential-actions-autolock`)。
- 自動ロック・アイドルタイマー(`credential-actions-autolock`)。
- 検索アルゴリズムの高度化(ファジーマッチの独自実装等)。

## Decisions

### 1. フロントエンドはフレームワークを使わず素のHTML/CSS/TypeScriptで実装する

画面数が2つ(アンロックフォーム・検索結果一覧)と少なく、状態管理も単純なため、React/Svelte等のフレームワーク導入は本changeの時点ではオーバーエンジニアリングと判断する。UIが将来的に複雑化した場合は別途検討する。

### 2. WebViewはbw serveのHTTPエンドポイントに直接アクセスしない。Tauri commands経由のIPCに統一する

WebView側のJavaScriptから `http://localhost:<port>` に直接fetchするのではなく、Tauriの `invoke()` によるIPC経由でRustコア(`bw-serve-backend` のクライアントラッパー)を呼び出す。これにより、bw serveの待受ポート番号やHTTP APIの詳細をWebView側に一切露出させず、フロントエンドの攻撃面(XSS等が万一発生した場合の被害範囲)を最小化する。

代替案として検討したが採用しなかったもの:
- WebViewから直接 `fetch("http://localhost:<port>/...")`: 実装は単純だが、ポート番号・APIをフロントエンドに露出させることになり、`bw-serve-backend` の設計意図(内部実装の隠蔽)に反する。

### 3. 検索はデバウンス付きでIPC呼び出しする

キー入力のたびに即座にIPCを呼ぶのではなく、短いデバウンス(数十〜数百ms、`fullscreen-fzf-ui` の `every(N)` 調整と同様に実装時の体感で決定)を挟んでからアイテム検索を呼び出す。

### 4. アンロックフォームはエラー時にメッセージを表示し、再入力を許可する

マスターパスワード誤りの場合、`bw-serve-backend` からのエラーをそのままフォームにエラーメッセージとして表示し、入力フィールドはクリアして再入力を促す。v1.0.0では試行回数制限やロックアウトは実装しない(`bw` CLI自体、あるいはBitwardenサーバ側のレート制限に委ねる)。

## Risks / Trade-offs

- [`bw serve` の検索が現行の `fzf` ファジー検索と同等の体験を提供しない可能性がある(部分一致 or トークン一致止まりで、タイポ耐性や語順入れ替えへの対応がない等)] → 実装時に実際の挙動を検証し、必要であれば軽量なクライアント側の再ランキング処理を検討する。本changeでは `bw serve` の検索結果をそのまま採用することを既定とする。
- [デバウンス間隔が長すぎると体感が鈍く、短すぎるとバックエンド呼び出しが過多になる] → 実装時に体感で調整する。
- [WebViewとRustコア間のIPC往復がホットキー押下直後の初回表示速度に影響する可能性] → 検索ボックスへの自動フォーカスとウィンドウ表示自体はIPCを待たずに即座に行い、体感速度を優先する。

## Migration Plan

- `menubar-hotkey-shell` のプレースホルダ内容を本changeの実装で置き換える。
- ユーザー向け影響: 検索・一覧閲覧が可能になるが、コピー等のアクションはまだ実行できない中間状態が続く。
- ロールバックはコミットのrevertで対応可能。

## Open Questions

- `bw serve` の `/list/object/items?search=...` の実際のマッチングアルゴリズム(部分一致/トークン一致/ファジー)は実装時に検証する。
- ショートカットヒントの正確なUI配置・スタイリングは実装時に詰める。
