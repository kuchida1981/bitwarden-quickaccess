## Context

`bw-serve-backend` によりvaultへのアクセスを担うバックエンドは用意できたが、まだユーザーが呼び出す手段がない。本changeでは、1Password Quick Access相当の「どこからでもホットキーで呼び出せる」骨格(メニューバー常駐 + グローバルホットキー + ポップアップウィンドウの開閉)を実装する。ポップアップの中身(検索・コピー操作)は後続changeのスコープ。

対象OSはmacOSのみ(v1.0.0スコープ)。

## Goals / Non-Goals

**Goals:**
- メニューバー常駐アイコンとコンテキストメニュー(ロック状態表示・終了)を実装する。
- グローバルホットキー `⇧⌘Space` でポップアップウィンドウを表示/非表示トグルする。
- ポップアップはフォーカスを失うと自動的に閉じる。
- ログイン時自動起動のオン/オフ設定を実装する。

**Non-Goals:**
- 検索ボックス・アイテム一覧・コピー/ブラウザで開くアクション(`quickaccess-search-ui` / `credential-actions-autolock`)。
- ホットキーのユーザーカスタマイズ設定UI(固定割当のみ)。
- 配布パッケージング・コード署名(`gui-distribution-and-tui-removal`)。

## Decisions

### 1. トレイアイコンは Tauri の tray 機能を使う

TauriのTray API(`tauri::tray`)でメニューバーアイコンとコンテキストメニューを実装する。アイコン画像はロック状態(未接続/ロック済み/アンロック済み)ごとに用意し、`bw-serve-backend` の内部状態変化イベントを購読してアイコンを差し替える。

### 2. グローバルホットキーは `tauri-plugin-global-shortcut` を使う

`⇧⌘Space` を登録する。登録失敗(他アプリとの衝突等)はエラーログに記録し、アプリ自体は起動を継続する(v1.0.0ではリマップ設定を提供しないため、衝突時の代替手段はユーザーに対しREADME等で案内する形とする)。

macOSではグローバルホットキー・キーボードイベント監視に **アクセシビリティ権限(またはInput Monitoring権限)** の許可がOSダイアログ経由で必要になる場合がある。初回起動時にこの権限リクエストが発生することを前提に設計し、権限未許可時はホットキーが機能しない旨をトレイメニュー等でユーザーに分かる形にする。

### 3. ポップアップウィンドウはトグル方式、フォーカスロストで自動クローズ

ホットキー押下でウィンドウの表示/非表示を切り替える。ウィンドウの `blur`(フォーカスロスト)イベントを監視し、自動的に非表示にする(1Passwordと同様の挙動)。表示位置は画面上部中央(Spotlight/1Password Quick Accessに近い配置)とする。

### 4. ログイン項目登録は macOS `SMAppService` を使う

Tauriの `tauri-plugin-autostart` は内部的にmacOSでは `SMAppService`(または `SMLoginItemSetEnabled` 系のレガシーAPI)を利用する実装を持つため、これを採用する。オン/オフの状態はアプリの設定として永続化し、トレイのコンテキストメニューからトグルできるようにする。

## Risks / Trade-offs

- [グローバルホットキーがOS標準または他アプリのショートカットと衝突する] → v1.0.0ではリマップ設定を提供しないため、衝突時はREADMEでの手動回避案内に留める。将来のカスタマイズ設定は非目標として明記済み。
- [macOSのアクセシビリティ/Input Monitoring権限がユーザーに許可されないと、ホットキーが機能しない] → 権限未許可状態をトレイメニュー等で分かるようにし、無言で機能しない状態を避ける。
- [フォーカスロストでの自動クローズが、ユーザーの意図しないタイミング(例: 別ウィンドウへの一瞬のフォーカス移動)で発生する] → 実装時に体感で調整する。

## Migration Plan

- `bw-serve-backend` の上に追加する形で、既存コードへの破壊的変更はない。
- ユーザー向け影響: 開発ビルドを起動すると常駐アイコンとホットキーが有効になる。ただし検索・コピー機能はまだ持たないため、実利用にはまだ耐えない中間状態。
- ロールバックはコミットのrevertで対応可能。

## Open Questions

- ポップアップウィンドウの正確な表示位置・サイズは実装時に体感で決定する。
- アクセシビリティ権限が拒否された場合のUX(再度促す導線など)は実装時に詰める。
